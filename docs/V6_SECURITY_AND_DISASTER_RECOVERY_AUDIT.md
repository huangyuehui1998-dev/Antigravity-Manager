## 二、核心安全机制与容灾体系深度评审

### 2.1 Serde Default 结构体韧性与向后兼容性（评审：满分）
- **架构价值**：在 Rust 强类型静态序列化体系中，版本迭代最易导致反序列化崩溃（如新增 `provider`、`tier`、`consumption` 等字段）。
- **防御机制**：V6 方案强制推行 `#[serde(default)]` 与 `Option<T>` 规约，确保：
  1. 旧版数据读取时缺失新字段自动赋予标准默认值，不抛 `missing field` 异常；
  2. 结合 `#[serde(skip_serializing_if = "Option::is_none")]`，保持 JSON 极简，且老版本软件遇未知字段依然可平滑忽略。

### 2.2 空索引自我覆盖熔断护栏（评审：满分，定海神针）
- **致死病因识别**：原有逻辑在遇到解析失败或便携拔插时，扫描 `accounts/` 若返回 0，会直接生成包含 0 个账号的空索引并原子写盘，造成已有索引被“合法抹零”的灾难性事故。
- **熔断设计**：V6.0 引入熔断器（Circuit Breaker），当恢复出的账号数量为 0 时：
  - **强制拒绝覆盖**：绝不调用 `save_account_index` 覆写物理磁盘上的已有索引文件；
  - **硬件锁死隔离态**：进入只读保护模式，保留现场，触发系统级高危预警与自愈日志。

### 2.3 带时间戳版本化备份链（评审：满分）
- **彻底根治单一覆写缺陷**：废除固定的 `accounts.json-backup` 单一文件机制，升级为带纳秒时间戳的滚动备份链：`accounts.json.backup-{timestamp}-{uuid}.json`。
- **备份轮转与不可篡改**：支持保留最近 5~10 个健康版本，即使连续发生两次异常启动，最早的干净历史快照依然完好无损。

### 2.4 `.agpack` 加密跨设备迁移设计（评审：优秀，待规范落地）
- **解耦 Machine-UID 锁死**：将绑定硬件机器码的单机 AES-256-GCM 存储，升级为支持便携分发的独立加密包 `.agpack`，使用用户主密码通过 Argon2id 派生密钥加解密，实现跨操作系统与跨工作站的安全穿透。

### 2.5 `.gitignore` 终极封堵与 GitHub 零泄露（评审：优秀）
- **全方位阻断凭证出境**：在根目录 `.gitignore` 中彻底封杀：
  `antigravity_accounts_*.json`、`*.agpack`、`accounts/`、`accounts.json*`、`*.db`、`*.vscdb`。彻底杜绝任何形式的用户 OAuth 凭证、Refresh Token 与私有会话泄露至公共代码仓库。

## 三、四大极限实战场景安全性与容灾防御力审查

### 场景 1：跨设备便携拔插（Portable Drive Plug / Unplug）
- **风险暴露点**：用户将 `.antigravity_tools` 目录置于移动硬盘或 U 盘，在 PC-A 与 PC-B 之间切换。PC-B 的硬件 `machine_uid` 必然不同，直接解密 `accounts/*.json` 将 100% 触发 AES-GCM tag 校验失败。
- **V6 防御力表现**：**98/100 分**。
  - **空索引熔断** 阻止了 PC-B 将移动硬盘上的 `accounts.json` 抹零；
  - 启动时自动将状态转为“硬件环境变更锁定”，引导用户通过 `.agpack` 导入或输入主密码重新绑定当前设备；
  - 路径自举模块 `data_dir.txt` 兼容 Windows 跨盘符及 UNC 相对路径，防范盘符漂移（如 D 盘变 E 盘）。

### 场景 2：突发断电 / 异常退出（Sudden Power Loss / Crash）
- **风险暴露点**：批量导入或代理高并发流式写入时，系统断电或进程被强杀，导致文件仅写入半截或数据库损坏。
- **V6 防御力表现**：**96/100 分**。
  - `write_atomic` 深度封装了 Windows 底层 `MoveFileExW` 并启用 `MOVEFILE_WRITE_THROUGH (0x8)`，配合 `file.sync_all()`，物理穿透操作系统写缓存，杜绝 0 字节半截文件；
  - SQLite 开启 WAL 模式结合 MPSC 单线程异步批量刷盘，即使断电，未提交事务自动回滚，数据库自身 B-Tree 结构 100% 保持自洽。

### 场景 3：多版本升降级与回退（Multi-Version Upgrade & Downgrade）
- **风险暴露点**：V6.0 写入了包含 Kiro 账号或 5H 滑动窗口的新字段，用户回退至 V5.x 导致旧版本崩溃或损坏新数据。
- **V6 防御力表现**：**95/100 分**。
  - Rust 结构体 `Account` 与 `AccountSummary` 继承了无损解构契约，全部新增属性均有默认值；
  - 数据库表变更遵循 `CREATE TABLE IF NOT EXISTS` 与无损自愈回填，降级时 V5.x 忽略扩展字段正常运行，再次升级回 V6.0 时历史数据无损读取。

### 场景 4：公网 Git Push / 开源防泄露（Public Git Push Zero-Leak）
- **风险暴露点**：开发者在本地调试、压测时导出真实账号或流量 dumps，使用 `git commit -a` 误提交至 GitHub。
- **V6 防御力表现**：**92/100 分**。
  - `.gitignore` 将账号体系、分片目录与 `.agpack` 封死；
  - 即使不慎提交了 `accounts/` 下的物理文件，其内部内容亦受到 AES-256-GCM 硬件指纹加密（`ag_enc_v2_`），公网无法直接逆向明文。

## 四、迈向 100 分满分还需收口的最后 2 个落地执行边界

为实现 100% 无瑕疵的企业级生产交付，必须在具体编码实现中恪守以下 2 个落地执行边界：

### 边界 1：跨设备解密失败进入“三态安全沙盒（HardwareLocked Tri-State）”
- **执行规约**：
  在 `load_account_at_path` 捕获到 `failed_to_decrypt` 时：
  1. **明确状态定性**：严禁归类为“损坏数据（Corrupted）”，必须显式返回错误类型 `ErrorKind::HardwareKeyMismatch`；
  2. **三态隔离**：运行时账号标记为 `HardwareLocked` 态，保留本地原文件绝对不动，严禁触发清理或重写；
  3. **交互闭环**：UI 呈现高清晰度黄色锁形徽标，提供“输入迁移密钥解锁”或“重新登录授权此机器”，解除硬件绑定后方可重新持久化。

### 边界 2：湖仓双库增量对齐的高水位线（High-Watermark Sync Checkpoint）
- **执行规约**：
  在 `analytics_hub.db` 与 `token_stats.db` 之间设立无锁时序检查点：
  1. 在 `token_stats.db` 的 `sys_meta` 表中记录最后同步的 `last_synced_timestamp`（或 `max_usage_id`）；
  2. 启动自愈检测时，扫描器仅需比对 `SELECT max(timestamp)`，只将大于高水位线的新增差量数据批次增量写入，避免每次启动触发对 25.7 亿数据的全量遍历，彻底消灭启动假死风险。
